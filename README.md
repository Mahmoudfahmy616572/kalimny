# Kalimny — AI Voice Language Learning Platform

> **كلمني** — a real-time voice-call language-learning platform where learners practice English, French, Spanish, and German with a lifelike AI tutor that talks, jokes, and corrects them in Egyptian Arabic.

**Live demo:** https://kalimny.vercel.app

Kalimny is not a chat-bot with a text box. It opens a **live, low-latency bidirectional audio session** between the learner and a Gemini-powered voice tutor, renders the tutor as an **animated 3D character built entirely in code** (no external 3D assets), and tracks the learner's progress through a structured CEFR-aligned curriculum.

## Product overview

Traditional language apps teach vocabulary with flashcards or text chat. Kalimny targets the hardest skill — **speaking** — by placing the learner on a simulated phone call with a native-sounding AI tutor.

Key design decisions:

- **The tutor speaks Egyptian Arabic by default**, dropping target-language words and phrases into the conversation and explaining them in Arabic. This avoids the "pure-immersion confusion" that stops beginners from progressing, while still maximizing target-language exposure.
- **The tutor is a character, not an assistant.** Each persona has its own energy level, vibe, humor style, correction style, and signature catchphrases. It argues, teases, jokes, and reacts emotionally — but always steers the conversation back to the lesson.
- **Personas are per-language** — two distinct characters for each of the four languages (8 total), each with a unique voice, look, and personality.
- **Progress is curriculum-driven**, not free-form. Every session advances a linear unit within the learner's CEFR level.

## Core features

### Voice
- **Real-time bidirectional audio** over a WebSocket using the Gemini Live API (`BidiGenerateContent`), with PCM 16 kHz input and 24 kHz output.
- **Ephemeral token issuance** — the server mints a short-lived, single-use token so the master API key never reaches the browser.
- **Interruption handling** — when the learner speaks over the tutor, playback stops and the tutor's mid-sentence transcript is flushed.
- **Resilient reconnection** — the client stores the server-issued *session resumption handle* and transparently reconnects with exponential backoff, preserving conversation context across network drops.
- **Context window compression** — enables long sessions beyond the default 15-minute cap.

### 3D avatar
- A full character (head, hair, eyes with blinking, eyebrows, mouth, ears, neck, body, and jointed arms with shoulder + elbow) **generated procedurally in code** with React Three Fiber + Three.js.
- **Lip-sync driven by live audio amplitude** — the mouth mouth-shape, head nods, and hand gestures all react to the real level of the tutor's audio stream.
- **Animation state machine** with moods (`neutral`, `happy`, `excited`, `thinking`, `listening`) and triggered gestures (greeting wave, cheer).

### Curriculum & progress
- **Linear CEFR units** (A1–C2), where each unit is one session. Units are described in Arabic with vocabulary themes, grammar focus, and sample phrases; the tutor *generates* the actual target-language content live based on the unit and the learner's interests.
- **Progress map** UI shown on the home page and in the session header.
- **Session summaries** generated by Gemini Flash at the end of a lesson (vocabulary, phrases, grammar) and persisted for review.
- **Unit advance rule**: a session only advances the unit if it consumed at least **60%** of its allocated time; otherwise the unit repeats.

### Personas
- Language filter + persona grid on the home page; the selected persona is saved to the user's account and used as the default next time.
- Per-persona 3D look (colors, hair style, skin tone) and per-persona Gemini voice.

### Accounts & quota
- Supabase Auth (email/password) with server-side session validation.
- **Email verification via a 4-digit OTP** delivered over our own SMTP relay (Brevo), replacing Supabase's default confirmation email (which is fixed at 6 digits and rate-limited). See [Sign-up & email OTP](#sign-up--email-otp).
- **Trial + subscription model** enforced atomically in the database.

## Architecture

Kalimny is an **npm-workspaces monorepo** with a strict separation between the shared domain model and the app.

```
kalimny/
├── apps/
│   ├── web/          # Next.js 16 application (App Router, RSC)
│   └── mobile/       # Flutter starter, untouched (the web app is the product — see Status)
├── packages/
│   └── shared/       # Framework-agnostic domain model (TS, consumed directly)
└── supabase/
    └── migrations/   # SQL migrations + SECURITY DEFINER RPCs
```

A key architectural choice: **`packages/shared` is plain TypeScript consumed directly by the app** (no build step). It contains the *domain vocabulary* — languages, curriculum, personas, lesson economy, and the voice-provider contract — so types and business rules can never drift between server and client.

### The voice-provider abstraction

The app codes against a single interface, and the concrete provider is an implementation detail:

```ts
interface VoiceProvider {
  connect(options: SessionOptions): Promise<void>;
  disconnect(): Promise<void>;
  sendAudio(chunk: ArrayBuffer): void;
  sendText(text: string): void;
  on(handler: (event: VoiceEvent) => void): () => void;
}
```

`VoiceEvent` is a normalized union (`status`, `user-transcript`, `tutor-transcript`, `audio-out`, `interrupted`, `turn-complete`, `correction`, `usage`, `error`). The UI consumes only these events and knows nothing about Gemini or its wire protocol — so a new provider (e.g. OpenAI Realtime) can be dropped in without touching any component.

## How the voice session works

End-to-end flow of a single lesson:

1. **Page load** — `/session?lang=en&level=A1&persona=en-layla` renders behind a `<Suspense>` boundary. The server (`instant = false`) reads the authenticated user, resolves the persona, loads the lesson-quota account, and builds the current `LessonPlan` (unit + learner goal + interests + recap words from the last summary).

2. **Token request** — the client `POST`s to `/api/voice/token`. The server:
   - validates the session,
   - **atomically reserves lesson credit** (`startLesson` RPC — trial lesson or subscription minutes),
   - mints a Gemini **ephemeral auth token** (`uses: 1`, expiry = lesson length + margin),
   - returns the token + model + session id.
   If token minting fails *after* the reservation, the reservation is **voided** so the learner is never charged for a lesson that never ran.

3. **WebSocket setup** — the `GeminiLiveProvider` opens the constrained Live endpoint with the token, then sends a `setup` message containing:
   - the model and `responseModalities: ["AUDIO"]`,
   - the per-persona `voiceName`,
   - `systemInstruction` built from the persona + lesson plan (`buildSystemInstructions`),
   - `contextWindowCompression: { slidingWindow }`,
   - `sessionResumption`,
   - input + output audio transcription.

4. **Live loop** — mic audio is captured via an `AudioWorklet`, resampled to 16 kHz PCM, and streamed as `realtimeInput`. Server audio frames arrive as **binary** WebSocket messages; the client decodes them (handling `ArrayBuffer`/`Blob`), parses JSON, and pushes PCM into a `PcmPlayer` for output. Transcript fragments update the chat panel; `interrupted` / `turnComplete` end the turn.

5. **Reconnection** — on unexpected close, if a resumption handle exists the provider reconnects with backoff `[500, 1s, 2s, 4s, 8s]` and resumes the same session under the same token.

6. **End of lesson** — the client reports duration to `/api/voice/lesson/end`. The server settles the quota (`endLesson`), and — inside `after()` so it never blocks settlement — triggers **summary generation**. A `/api/voice/summary-status` endpoint is polled by the UI to display the finished summary card.

## Sign-up & email OTP

Email confirmation is handled by a **custom 4-digit OTP flow** rather than Supabase's built-in email, for two concrete reasons: Supabase's OTP length is fixed at 6 digits (not configurable), and its email sender is rate-limited.

1. **Sign-up** — `signUpAction` creates the user with `supabase.auth.signUp`. If no session is returned (confirmation required), it calls `issueEmailOtp` → `create_email_otp` (RPC) to store a **SHA-256 hash** of a random 4-digit code with a 10-minute TTL and a 5-attempt cap, then sends the code via **Brevo SMTP** (nodemailer) and redirects to `/verify?email=…`.
2. **Verify** — `/verify` collects the 4 digits and calls `verifyOtpAction`, which runs `consume_email_otp` (RPC). On `ok`, the server confirms the user's email through the Supabase admin API and redirects to `/onboarding`. Wrong codes increment the attempt counter; re-issuing a code resets it.
3. **Resend** — `resendOtpAction` re-issues a fresh code (resolving the user id by email via the admin API).
4. **Login** — `signInAction` redirects users whose email is still unconfirmed to `/verify`.

The **code is never stored in plaintext** — only its hash — and the `email_otps` table has RLS enabled with no policies, so it is reachable only through the `SECURITY DEFINER` functions, which are granted to `service_role` alone.

## The 3D avatar

The avatar is the most distinctive piece of front-end engineering in the project: a **fully procedural character** built from Three.js primitives — no imported models, no rigged assets.

- **Composition** (`character.tsx`): a head sphere, six hair styles, eyes with blinking, eyebrows, a mouth, ears, a neck, a capsule body, and two arms each with a shoulder and elbow joint.
- **Per-persona looks** (`persona-look.ts`): skin, hair color/style, shirt color, and accessory tuning for all eight characters.
- **Audio-driven lip-sync**: the component samples the live output level via a `getLevel()` probe each frame and maps it to mouth open/close, head nods, tremors, and gesturing arms. A deterministic fallback synthesizes a speech-like envelope if real level reads fail, so the character is never "dead" on unusual audio setups.
- **Mood + gesture state machine**: `AvatarMood` blends facial expressions (`SMILE` / `BROW` / `TILT` tables) and gesture triggers (`waveKey` for the greeting, `cheerKey` for celebration).
- **Performance**: `dpr={[1, 1.75]}`, dynamic import with `ssr: false`, a skeleton loader, and a single `useFrame` loop with per-frame interpolation.

> A notable debugging win: React Three Fiber's render loop **already consumes `clock.getDelta()`** before `useFrame` runs, so reading it manually returns ~0 and freezes every lerp. The fix was to use the `delta` value R3F passes as the callback's second argument — restoring mouth and arm motion.

## Personas & voice DNA

Each persona is a `PersonaSpec` with:

- identity (id, name, emoji, language, level),
- a **unique Gemini voice** mapped to its gender,
- a **`PersonaStyle`** (`energy`, `vibe`, `humorStyle`, `correctionStyle`, `catchphrases`),
- teaching traits (accent, topics, `tutorTalkRatio`, `maxCorrectionsPerTurn`, humor flag).

`buildSystemInstructions(persona, lessonPlan)` compiles all of this — plus the current unit, the learner's goal/interests, and last-lesson recap words — into a detailed system prompt that makes the tutor behave like a close Egyptian-Arabic-speaking friend, not an assistant.

**The roster (8 personas, 2 per language):**

| Language | Personas | Voices |
|---|---|---|
| English | ليلى ☕ · كريم 🎧 | Sulafat · Achird |
| French | كاميل 🥐 · نادين 🎨 | Algieba · Vindemiatrix |
| Spanish | صوفيا 💃 · دييغو 🌶️ | Laomedeia · Sadachbia |
| German | يوناس 🍺 · لينا ☀️ | Orus · Zephyr |

**Persona resolution priority** on the session page:
1. explicit `?persona=` if valid *and* matching the session language,
2. the learner's saved choice (same language check),
3. the language default.

A mismatched or unknown id never overwrites the saved choice.

## Curriculum & progress

- **`curriculum.ts`** defines linear units per CEFR level. Units are **descriptive, not hardcoded vocab lists** — the tutor generates the target-language vocabulary and sentences live from the unit's themes + grammar + learner interests, so the *same* unit definitions serve all four languages without duplicated content.
- **Progress cursor** — `user_progress(unit_index)` is tracked per `(user_id, language)`.
- **Advance/Repeat rule** — `isSessionComplete()` uses `SESSION_COMPLETE_RATIO = 0.6`: a lesson only advances the unit if ≥60% of its allocated time was used.
- **Summaries** — `gemini-3.8-flash` produces a structured summary (words, phrases, grammar) from the transcript + unit context, persisted to `lesson_summaries` and surfaced in the UI.

## Lesson quota & billing model

All quota logic lives **in the database** as atomic `SECURITY DEFINER` RPCs — there is a single source of truth and no counting logic in TypeScript.

- **Trial**: 3 free lessons × 15 minutes.
- **Subscription**: 250 minutes / month for 210 EGP; selectable lesson lengths 15 / 30 / 50 minutes (max 90).
- The base unit is **minutes**; "number of lessons" is derived (`credit ÷ lesson length`).
- Failures are non-destructive: a failed token mint voids the reservation; summary generation failure never breaks quota settlement.

Postgres (Supabase) with RLS. Migrations in `supabase/migrations/`:

| Migration | Purpose |
|---|---|
| `0001_lessons.sql` | Core lesson tables |
| `0002_lesson_accounts.sql` | Lesson accounts + atomic trial/paid RPCs |
| `0003_subscription_grants.sql` | Subscriptions + grants |
| `0004_fix_ambiguous_columns.sql` | RPC column disambiguation fix |
| `0005_user_preferences.sql` | Onboarding preferences + `get_lesson_plan_context` |
| `0006_persona_choice.sql` | Saved persona + `save_persona` RPC |
| `0007_grants.sql` | Explicit table grants + default privileges (Supabase's Oct 2026 change) |
| `0008_email_otp.sql` | `email_otps` table + `create_email_otp` / `consume_email_otp` RPCs |
| `0009`–`0018` | Password hardening, per-level progress, XP ledger, lesson exams, exam-gated advancement, XP awards |

**18 migrations in total.** All writes go through `SECURITY DEFINER` RPCs; tables expose *select-own* policies only, and the XP award table is revoked from `authenticated` entirely.

## Security model

- **Never trust the client**: lesson duration is normalized server-side; the master Gemini key never leaves the server; tokens are single-use and short-lived.
- **Auth on every request**: the token and lesson endpoints validate the Supabase session; the session route redirects unauthenticated users.
- **Server-only modules** (`import "server-only"`) guard quota, summary, and Supabase-server code from leaking into client bundles.
- **Hashed OTPs** — verification codes are stored only as salted SHA-256 hashes, with a TTL and an attempt cap; the table has RLS with no policies and is reachable solely via `service_role`-only RPCs.
- **Secrets** live only in `.env.local` / Vercel env vars; nothing sensitive is committed.

## Running locally

**Prerequisites:** Node ≥ 20, and a Supabase project + a Gemini API key.

```bash
# 1. Install
npm install

# 2. Configure apps/web/.env.local
GEMINI_API_KEY=...
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...
# Email OTP (Brevo SMTP relay)
SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=587
SMTP_USER=...
SMTP_PASS=...
SMTP_FROM=...
SMTP_FROM_NAME=Kalimny

# 3. Apply migrations (Supabase SQL editor or CLI), then:
npm run dev        # http://localhost:3000
```

Useful scripts (run from the repo root):

```bash
npm run dev        # start the web app
npm run build      # production build
npm run lint       # eslint
npm run typecheck  # tsc --noEmit
```

## Engineering highlights

Things worth calling out on a résumé:

- **Real-time voice, end to end.** Implemented a full duplex-audio pipeline: `AudioWorklet` capture → resample to 16 kHz PCM → WebSocket → decode binary Gemini frames → `PcmPlayer` playback, with interruption and turn-complete handling.
- **Zero-leak key handling via ephemeral tokens.** The master API key is server-only; the browser receives a single-use, time-boxed token minted per lesson.
- **Transparent session resumption.** Automatic reconnection with exponential backoff that preserves context using the server's resumption handle — the learner never sees a dropped call.
- **A provider-agnostic voice layer.** A single `VoiceProvider` interface + normalized event stream decouples the entire UI from Gemini.
- **A fully procedural 3D character.** No assets — a rigged-looking avatar with audio-driven lip-sync and a mood/gesture state machine, built from Three.js primitives.
- **Distinct AI personalities.** A structured `PersonaStyle` compiled into rich system instructions, giving each of eight tutors a distinct voice, energy, humor, and correction style.
- **Database-enforced economy.** Atomic `SECURITY DEFINER` RPCs make quota handling race-free and consistent; TypeScript holds no billing logic.
- **Custom email-OTP verification.** Built a hashed, TTL'd, attempt-capped 4-digit OTP flow (with its own Brevo SMTP relay) to work around Supabase's fixed 6-digit, rate-limited confirmation email.
- **Modern Next.js 16 patterns.** Cache Components, Partial Prerendering, `<Suspense>` boundaries on dynamic routes, and React Server Components — with server actions for auth/onboarding.
- **Monorepo discipline.** A framework-agnostic shared domain package (consumed as raw TS) keeps server and client types and rules in lockstep.

## Status & limitations

Everything above is what is actually built. This is what is not — so nobody has to discover it:

- **The product is the web app.** `apps/mobile` is still the untouched Flutter starter (counter app). It is reserved as the future native client, not a shipped app.
- **Billing is manual.** Subscription grants happen server-side (`grant_subscription` is revoked from `authenticated`); the Paymob checkout is not wired yet.
- **No automated tests on the web app.** The domain helpers are pure functions and were exercised manually; the only test file in the repo belongs to the Flutter template.
- **Exam-gated advancement exists for English only.** The `fr` / `es` / `de` exam banks are empty, so those languages advance on lesson minutes alone.
- **Placement is partially session-only.** Level and language persist through `save_home_preferences`; the extra `placement_*` diagnostics are displayed but not written, because the tables expose select-own policies only.
- **One declared-but-unused event.** The `correction` event is typed and rendered in the transcript, but the provider does not emit it yet.
